Universal Tool Mastery Layer

The framework is not the subject, and it is not optional. Every major technology is learned at two levels: the underlying engineering concept and the concrete tool that implements it.

  1. Orient: purpose, abstraction, mental model.
  2. Map primitives: core objects, APIs, configuration, lifecycle, execution semantics.
  3. Build: implement the conceptual pattern with the tool.
  4. Inspect: inspect state, traces, logs, artifacts, and relevant implementation behavior.
  5. Break: deliberately inject failures, invalid inputs, concurrency, retries, and edge cases.
  6. Debug: explain the mechanism behind the failure and fix it from evidence.
  7. Compare: reproduce the pattern with another tool or without the framework.
  8. Defend: justify the tool, its guarantees, limitations, abstraction leaks, and trade-offs.

Every major technology must answer: What is it? How does it work? How do I use it? When should I use it? What happens when it breaks? What guarantees does it actually provide? Where does its abstraction leak?

Mastery target: conceptual + API + implementation + debugging + operational mastery + architectural judgment.
